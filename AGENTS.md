# Правила работы агентов

Общие правила для ChatGPT Work, Codex, Claude Code и других ИИ-агентов.
Единый журнал состояния и согласованного scope: [docs/PROJECT_LEDGER.md](docs/PROJECT_LEDGER.md).

## Перед работой

1. Проверь фактическую папку, `git remote -v`, `git status --short --branch`, текущую
   ветку и `git rev-parse HEAD`. Официальный origin —
   `https://github.com/lDiestrol/minecraft-launcher.git`.
2. Выполни `git fetch origin`, проверь `git rev-parse origin/main` и сравни рабочую
   ветку с актуальным main. Если fetch недоступен, явно укажи, что свежесть не проверена.
3. При незнакомых незакоммиченных изменениях остановись и сообщи владельцу;
   не перезаписывай их и не создавай автоматический stash. Известные изменения текущей
   задачи можно продолжать. Для чистой копии main допустим только безопасный fast-forward.
4. Прочитай Ledger и нужные специализированные документы. Не доверяй старым отчётам
   ИИ, названиям feature-веток или числу тестов без сверки с Git и кодом.
   Не начинай заново завершённые этапы. При расхождении зафиксируй проверенные факты.

Локальные пути различаются между компьютерами. На этом ноутбуке используется
`C:\Projetcs\minecraft-launcher`; написание `Projetcs` намеренное. Не навязывай этот путь
другим машинам и не исправляй его на `Projects`.

## Во время работы

- `main` сохраняет стабильную v0.6.0; интеграционная ветка следующей версии —
  `feat/v0.6.1`. Проверяй обе актуальные remote-ссылки. Разрабатывай промежуточные
  изменения в отдельных feature/docs/fix-ветках с PR в `feat/v0.6.1`.
  Не переключай существующую рабочую ветку без учёта её изменений и задачи.
  Только полностью завершённая v0.6.1 переносится в main одним Squash & Merge после
  явного согласования владельца. `release/v0.6.0` не меняется в этом треке.
- Соблюдай согласованный scope версии в Ledger; расширение требует согласия владельца.
  v0.6.1, v0.6.2 и серверный Pack Manager — отдельные направления.
  Не обновляй другие моды попутно; app version меняется только в согласованной
  release preparation, а packVersion/hosting — в отдельной соответствующей задаче.
- Сохраняй пользовательские игровые данные и действующие границы managed-файлов,
  профильных блокировок и совместимости протоколов.
- Не публикуй секреты, пароли, токены, внутренние IP/hostnames, SSH-ключи и
  административные credentials. Публичный клиент не должен содержать таких данных.
- Не меняй production Minecraft Server, Proxmox, LXC, NGINX или DNS без отдельного
  разрешения. План инфраструктуры не является разрешением на её изменение.
- Не выполняй destructive Git operations (`reset --hard`, `clean`, force push и
  аналогичные действия) без явного разрешения и проверки точных целей.
- Не выполняй commit, push, merge, tag или release без разрешения, если конкретная
  задача прямо не предусматривает это действие.

## Проверки и завершение

- После изменений запускай относящиеся к ним тесты. Для кода выполни применимые
  build/test/format проверки; для документации — Markdown, внутренние ссылки,
  отсутствие секретов и `git diff --check`. Format используй с `--verify-no-changes`.
- Разделяй новые результаты, исторические проверки и неподтверждённые сведения.
  При сбое укажи тест, результат и ограничение; не выдавай прошлый успех за текущий.
- Обнови Ledger: состояние, выполненные работы, проверки, проблемы и следующие шаги.
  Исправь затронутые специализированные документы; не создавай параллельный status-файл.
- В отчёте укажи изменённые файлы, первоначальную/итоговую ветку, HEAD/commit,
  результаты тестов и оставшиеся проблемы. Если commit не создавался, скажи это.

Нормативные схемы живут в документах протоколов, технические детали — в профильных
документах. Ledger хранит состояние и решения со ссылками, а не заменяет эти контракты.
