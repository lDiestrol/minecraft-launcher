## Подтверждённые факты

### Релиз и репозиторий

- Публичный репозиторий: <https://github.com/lDiestrol/minecraft-launcher>.
- Стабильный выпуск: [Minecraft Launcher v0.6.0](https://github.com/lDiestrol/minecraft-launcher/releases/tag/v0.6.0).
- Версия приложения в `Directory.Build.props`: `0.6.0`.
- Tag `v0.6.0` указывает на commit
  `1ae3ae74b1b70d92031fe8706f80f85e506efd56`.
- Релиз собран для Windows x64 как self-contained .NET 10 приложение через
  Velopack 1.2.158, PackId — `lDiestrol.MinecraftLauncher`, канал — `stable`.
- На релизном commit проходили 252 теста, build, format check, NuGet audit и
  проверки release feed.
- Пакеты не подписаны Authenticode; Windows SmartScreen может показывать предупреждение.

### Подтверждённый пользовательский сценарий обновления

Пользователь вручную подтвердил реальный путь обновления:

1. установка стабильной v0.5.0;
2. обнаружение v0.6.0 во встроенном update UI;
3. скачивание пакета из GitHub Releases;
4. применение обновления и автоматический перезапуск;
5. сохранение настроек Launcher;
6. успешный запуск Minecraft после обновления.

Это подтверждает production update path для указанной пары версий. Это не означает,
что будущие версии можно выпускать без повторной проверки feed, пакетов и installed E2E.

### Архитектура приложения

Solution сохраняет разделение .NET 10 / WPF / MVVM:

- `src/Launcher.Core` — модели, правила, контракты сервисов и координаторы операций;
- `src/Launcher.Infrastructure` — HTTP/JSON, настройки, файловая система, pack sync,
  CmlLib.Core, Velopack и Windows-specific реализации;
- `src/Launcher.App` — WPF UI, ViewModels, команды, диалоги и composition root;
- `tests/Launcher.Core.Tests` и `tests/Launcher.App.Tests` — автоматические проверки.

Подробности находятся в [architecture.md](architecture.md),
[game-launch.md](game-launch.md), [server-protocol.md](server-protocol.md) и
[pack-manifest.md](pack-manifest.md).

### Реализованные пользовательские функции

- onboarding и подключение к launcher server по HTTPS URL;
- получение и строгая проверка Server Protocol v1;
- выбор серверного профиля, offline nickname и RAM;
- подготовка Minecraft, Fabric и Mojang Java через CmlLib.Core;
- Pack Manifest v1, SHA-256 sync/repair и atomic publish managed-файлов;
- запуск выбранного профиля с автоматическим подключением к игровому серверу;
- Dark Gaming UI, адаптивная компоновка и тёмный WindowChrome;
- ручная и автоматическая проверка обновлений приложения через GitHub Releases;
- открытие папок профиля, `mods`, `resourcepacks` и `shaderpacks`;
- безопасное удаление только известных managed pack-файлов с сохранением
  пользовательских файлов;
- межпроцессная блокировка операций над одним профилем для Play, Repair, Delete,
  pack sync и всего времени жизни Minecraft process.

Текущее удаление managed pack-файлов не является полным удалением установки профиля
и не очищает общие Minecraft assets, libraries, versions или Java runtime.

### Хранение данных

- приложение Velopack: `%LOCALAPPDATA%\lDiestrol.MinecraftLauncher`;
- настройки, логи и Minecraft: `%LOCALAPPDATA%\MinecraftLauncher`;
- профиль: `%LOCALAPPDATA%\MinecraftLauncher\instances\<profile-id>`;
- общие данные: `assets`, `libraries`, `versions`, `runtime` внутри data root;
- managed state профиля: `instances/<profile-id>/.launcher/managed-state.json`.

Launcher не должен считать весь Minecraft содержимым одного instance-каталога.

### Текущая игровая сборка

По подтверждённому на момент этого снимка состоянию профиль WT #1 использует:

- Minecraft `26.1.2`;
- Fabric `0.19.3`;
- packVersion `1.0.1`.

Эти значения приходят из внешних `profiles.json` и `manifest.json`, а не задаются
версией приложения. Перед любыми действиями с pack hosting их нужно получить заново
из фактического production-источника.

### Контракты и границы безопасности

- Server Protocol остаётся версией 1.
- Pack Manifest остаётся версией 1 и управляет только разрешёнными путями
  `mods/` и `config/`.
- Строгий JSON отклоняет неизвестные поля; новые поля нельзя добавлять без
  согласованной эволюции schema и клиента.
- Обновление приложения Velopack, подготовка Minecraft runtime и синхронизация
  игрового pack — три независимых lifecycle.
- Публичный клиент не содержит административных SSH-ключей, токенов или внутренних
  адресов инфраструктуры.
- Пользовательские миры и unmanaged-файлы нельзя удалять без явного разрешения.

## Согласованные требования

- Следующая версия Launcher — узко ограниченная v0.6.1; её объём описан в
  [ROADMAP.md](ROADMAP.md).
- Расширенное удаление игровых данных относится к отдельной v0.6.2.
- Серверный Pack Manager развивается отдельно и не должен ломать v0.6.0,
  Server Protocol v1 или публичные URL. План: [PACK_MANAGER_PLAN.md](PACK_MANAGER_PLAN.md).
- Любая новая сессия разработки должна начинаться с clean Git, актуального `main`,
  чтения [AI_HANDOFF.md](AI_HANDOFF.md) и проверки фактических внешних данных.

## Идеи и предложения

- Добавить краткую машинно-проверяемую release checklist для будущих версий.
- По мере роста проекта выделить ADR для решений о запуске, хранении профилей и
  публикации pack, не переписывая нормативные документы протокола.
- Синхронизировать пользовательскую документацию с каждым стабильным выпуском.

Эти пункты не входят автоматически в v0.6.1.
